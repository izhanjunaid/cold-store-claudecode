## Phase 14 — Rooms & Racks (2026-07-10 → 2026-07-11)

Terminology decision: **UI says "Room", DB/API/code keep `chamber`** (zero rename risk to the deployed production DB); racks are additive. A lot's bags may spread over several racks of its room (`lot_rack_placements`, per-rack bag counts); unallocated bags are implicitly "Unplaced" — placement is optional at inbound and existing production lots migrate as fully unplaced. Per-rack capacity is a soft warning only; the hard capacity check stays at room level. Placements are restricted to racks of the lot's room; rack→rack moves may be partial, inter-room moves are whole-lot (preserves the single `Lot.chamberId` FK that occupancy math, reports, and billing depend on).

- **DB**: migration `20260710000000_0005_rooms_and_racks` — `racks` (unique name per chamber, position, soft capacity, is_active), `lot_rack_placements` (unique lot+rack, bags>0 CHECK, lot FK CASCADE so test-reset/lot cleanup stays FK-safe), `lot_movements` append-only log (`PLACEMENT | RACK_TRANSFER | ROOM_TRANSFER | WITHDRAWAL_PICK`, from/to chamber+rack, reason, moved_by). Purely additive. Seed: 16 racks across the 4 seed chambers; test-seed racks for the fixed test chambers.
- **API**: rack CRUD (`POST /v1/chambers/:id/racks`, `PATCH /v1/racks/:id` MANAGER+, deactivation blocked while stock is placed), `GET /v1/racks/:id/lots` (drill-down with marka), chamber list/detail extended with `rack_count` / `racks[]` (per-rack occupancy) / `unplaced_bags`. Lot side: `placements` accepted atomically on `POST /v1/lots`, `GET/PUT /v1/lots/:id/placements` (full-replace, PLACEMENT movement deltas, rack-overflow warnings via the existing `warnings[]` pattern), `POST /v1/lots/:id/move` (discriminated RACK partial / ROOM whole-lot with destination hard-capacity + commodity checks), `GET /v1/lots/:id/movements` (named timeline). Withdrawal finalize accepts `picked_from[]` (validated against placements, ≤ withdrawn qty) and auto-trims any remainder largest-placement-first inside the same tx (`WITHDRAWAL_PICK` logged; full close clears placements). Partial ownership transfer re-attributes trimmed placements onto the child lot on the same racks (bags never move; no movement rows). Gate-pass responses gain `related_location` ("Room → R-1 ×300, R-2 ×200").
- **PDFs**: bilingual A5 `placement-slip.html` (marka banner, rack allocation table, unplaced row) via `GET /v1/lots/:id/placement-slip`; A4 `rack-labels.html` (4 cut-out labels/sheet) via `GET /v1/chambers/:id/rack-labels`. Parchi label "Chamber/چیمبر" → "Room/کمرہ".
- **Web**: chambers screens migrated to TanStack Query (`qk.chambers`); shared `CapacityBar` extracted (fill bars were hand-rolled ×3); Rooms list (rack counts), Room detail (visual rack grid + per-rack lot drill-down with marka, MANAGER+ add/edit-rack dialog incl. the previously-missing edit affordance, Print Rack Labels), Room Map drill-down (rack mini-heatmap chips + Unplaced bucket), Create Room with a rack repeater; inbound form gains an optional `RackAllocationEditor` (remaining counter, one-tap "all on one rack", soft overflow hint); lot detail gains a Location card (room → rack chips + Unplaced badge, Edit Placement dialog, Move dialog with rack/room tabs + destination capacity preview, Placement Slip print) and a Movements timeline tab; withdraw page shows "Pick from" chips; outbound detail shows pick location and records optional per-rack picks at finalize; gate console rows show location + marka; lots list gains a Room facet filter; label sweep Chambers→Rooms (nav, dashboard, reports, settings label — the `chamber_capacity_warning_pct` settings key is unchanged).
